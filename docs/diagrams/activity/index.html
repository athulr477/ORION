Step-by-Step Operational Workflow

  1. Initial State (●): Triggered when a software developer pushes test commits with @traces("REQ-xxx") tags and opens or updates a Pull Request.
  2. Receive Pull Request and Ingest Requirements: FastAPI webhook handler intercepts the event and fetches the linked Jira requirements via JQL API.
  3. Decision Diamond 1 (Dual-Sided Analysis):
    • [semantic vector analysis]: Generates dense vector representations using FastEmbed ONNX (BAAI/bge-small-en-v1.5).
    • [structural assertion analysis]: Python ast.NodeVisitor parses comparison expressions (left, op, right) and normalizes measurement units (e.g. 200ms ↔ 0.2s).
  4. Execute Kuhn-Munkres Bipartite Matcher: Resolves global optimal alignment between requirement constraints and test assertions based on Dice keyword coefficient.
  5. Compute Hybrid Risk Score & Classify Status: Synthesizes alignment score and calculates true risk: $\text{Risk} = 1.0 - (0.6 \cdot \text{sem} + 0.4 \cdot \text{struct})$.
  6. Decision Diamond 2 (Drift Evaluation Gate):
    • [specification drift detected] (Risk > 0.60): Invokes Ollama Llama 3.1:8B Evidence-Grounded Verbalizer with AST assertion diffs to generate human-readable explanations (with attached document note), posts a failure GitHub Check Run to block merge, and files an audit warning comment on the Jira issue.
    • [traceability verified / compliant] (Risk ≤ 0.60): Bypasses drift alerting, unblocks the pull request, and transitions directly to the final state.
  7. Activity Final State (⊙): Traceability verification and compliance workflow successfully concludes.
